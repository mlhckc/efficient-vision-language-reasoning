# Project context for Claude and Codex

## Audit basis and scope

This context was assembled on 29 July 2026 from branch `v2-protocol` at base
commit `92da99c`. The worktree was clean before the collaboration files were
added. The audit read every tracked authored Python, shell, configuration and
Markdown file, all 22 experiment scripts, all experiment reports and all
tracked protocol evidence. It also inspected the schemas and inventories of
the local generated manifests, HDF5 stores, JSON/CSV results, figures and 116
checkpoints.

The workspace is about 61 GB. Most of that is not authored source:

- 148,854 extracted GQA JPEG images and a 21.8 GB archive;
- two raw GQA question JSON files and their 1.5 GB archive;
- 13 HDF5 embedding/token stores, including 5.8 GB of V3 tokens;
- 116 model checkpoints and other generated results;

Those binary, generated and third-party files were accounted for by path,
count, size, container schema, tensor shape, dtype, checkpoint signature and

package-managed environment state, not project source. `.git/` is repository
metadata. `__pycache__/` files are generated bytecode.

The contents of `data/v2/test_clean_targets.csv` were not opened. The audit
treated that path as opaque and used only previously verified structural facts
from the tracked protocol evidence. This remains binding for future agents.

## Current truth

This is an MSc Artificial Intelligence dissertation at the University of
Surrey, supervised by Prof. Miroslaw Bober. It asks whether closed-set visual
question answering can be performed efficiently using frozen CLIP features and
small trainable heads rather than a large autoregressive vision-language model.

The present state is:

- V1 is a completed legacy prototype. Its validation set was reused for
  checkpoint selection and reporting, so its figures are not confirmatory.
- V2 is complete through v2_07: a clean development protocol, global
  embeddings, multi-seed heads, capacity controls, interaction ablations,
  type/reliance analyses and 40k/100k/250k scaling.
- V3 is complete through v3_02a: token stores, a 40k question-conditioned
  latent-query reasoner, reference heads, repaired pooled step statistics,
  clustered uncertainty and CLS/patch diagnostics.
- No final clean-test evaluation exists. Every model result is a development
  result.
- On 30 July 2026, the user authorized E1 V3 100k/250k reasoner scaling,
  followed by E2, a frozen SigLIP-B/16 encoder swap on the global-embedding
  path, and E3, a 1000-answer vocabulary experiment. These experiments follow
  the S1-S3 corrections and P0-P3 preparation packets. Supervisor design
  feedback is still to be obtained and recorded when available, and each

## Scientific design

### Task and representation

The task is discriminative GQA answer classification over the V2 top-100
answer vocabulary. Image and question features come from one frozen OpenCLIP
ViT-B-32 model with `laion2b_s34b_b79k` weights. The shared encoder identity is
important: image and text features occupy the same 512-dimensional space.

V1/V2 global embeddings are unit-normalised float32 vectors. V3 stores all 50
projected visual tokens (CLS plus 49 patches) and packed projected question
tokens as unnormalised float16 arrays. The encoder is never trained.

### Global-head path

    raw GQA questions and images
      -> V1 or V2 manifests and answer labels
      -> frozen CLIP extraction
      -> row-aligned image/question vectors
      -> question-only, image-only, concat or fusion MLP
      -> best-on-dev checkpoint
      -> development accuracy and head-only efficiency

The global models are:

- question-only: `q`;
- image-only: `i`;
- concat: `[i, q]`;
- fusion: `[i, q, i * q, abs(i - q)]`.

Every standard model uses `MLPHead`: linear, ReLU, dropout and linear output.
The original fusion head is larger than concat because its input is twice as
wide; v2_03 controls this explicitly.

### Token-reasoner path

    keyed image and packed question token stores
      -> TokenStores and TokenDataset
      -> padded question batch with True = ignored padding mask
      -> 32 learned latent queries
      -> four blocks of question cross-attention,
         image cross-attention, latent self-attention and 4x FFN
      -> mean latent pool, LayerNorm and 100-way linear readout

The V3 reasoner has 21,099,620 trainable parameters, eight attention heads and
512-dimensional states. Cached-token training is the primary path; raw encoder
execution is not part of the training loop.

### HDF5 schemas

Legacy aligned stores have `image` and `question` datasets of shape `(N, 512)`
and dtype `float32`, plus a `label` dataset of shape `(N,)` and dtype `int64`:

- `embeddings/train.h5`: N = 40,000;
- `embeddings/val.h5`: N = 8,000;
- `data/v2/embeddings/train_40k.h5`: N = 40,000;
- `data/v2/embeddings/train_100k.h5`: N = 100,000;
- `data/v2/embeddings/train_250k.h5`: N = 250,000;
- `data/v2/embeddings/dev.h5`: N = 7,714;
- `data/v3/meanpatch/train_40k_meanpatch.h5`: N = 40,000;
- `data/v3/meanpatch/dev_meanpatch.h5`: N = 7,714.

Canonical keyed V2 stores are:

- `images.h5`: `ids (63,599)` plus `embeddings (63,599, 512) float32`;
- `questions.h5`: `ids (265,727)` plus `embeddings (265,727, 512)` with dtype
  `float32`; 184,432 unique texts are shared across IDs;
- `answers.h5`: 100 answer strings and raw/photo/ensembled `(100, 512)`
  prompt embeddings.

V3 token stores are:

- `image_tokens.h5`: `ids (63,599)` and `tokens (63,599, 50, 512)` with dtype
  `float16`, chunked one image at a time;
- `question_tokens.h5`: `ids`, `offsets` and `lengths` for 265,727 IDs plus
  packed `tokens (2,435,691, 512) float16`. Length includes SOT and EOT;
  identical texts share a packed block.

### Checkpoint families

The 116 `.pt` files form nine tensor-schema families:

- 21 standard concat heads, first layer `(512, 1024)`;
- 16 standard fusion heads, first layer `(512, 2048)`;
- 22 standard single-modality heads, first layer `(512, 512)`;
- 5 concat-wide heads, first layer `(979, 1024)`;
- 5 fusion-narrow heads, first layer `(268, 2048)`;
- 20 matched single-interaction heads, first layer `(351, 1536)`;
- 10 natural-width single-interaction heads, first layer `(512, 1536)`;
- 12 latent-query reasoner checkpoints with 32 learned `(512)` latents and
  four complete attention/FFN blocks;
- 5 direct-linear heads with `(100, 1024)` weights.

State dictionaries contain tensor weights only, not optimizer state or an
embedded vocabulary/hash contract.

## Experiment progression

### V1 legacy pipeline

- `1_prepare_gqa.py` downloads/extracts balanced question JSON, builds the
  frequency-ranked top-100 vocabulary, filters OOV questions and samples fixed
  40k/8k manifests.
- `2_extract_embeddings.py` downloads/extracts images, freezes CLIP, encodes
  each unique image/question, normalises vectors and writes aligned HDF5.
- `3_train_baselines.py` trains question-only, image-only and concat heads and
  records a majority reference.
- `4_train_latent_model.py` is historically named: it trains the handcrafted
  global fusion MLP, not the later latent-query reasoner.
- `5_evaluate.py` reloads best heads and measures development accuracy,
  parameter count, cached-vector latency, CUDA peak allocation and checkpoint
  size.

V1 development accuracies were majority 0.2339, image-only 0.2426,
question-only 0.4582, concat 0.5254 and fusion 0.5414. These are single-seed,
selection-biased prototype values.

### V2 experiments

- `v2_00_protocol`: replaces the leaked V1 validation design with image-level
  train/dev separation, independent seed streams, nested training prefixes and
  a blinded clean test. The independent verifier reports 99/99 checks passed;
  the 13 deterministic generated files were byte-identical on the recorded
  rebuild.
- `v2_01_embeddings`: creates canonical global stores and aligned 40k/dev
  views. The best image-only zero-shot prompt reaches 0.0795 versus majority
  0.2247. Question-conditioned zero-shot was not implemented, not impossible.
- `v2_02_multiseed`: trains four global models over seeds 0, 1, 2, 3 and 42.
  Mean dev accuracy is image-only 0.2344, question-only 0.4580, concat 0.5240
  and fusion 0.5384.
- `v2_03_param_match`: concat-wide reaches 0.5326 at 1.10M parameters and
  fusion-narrow reaches 0.5334 at 576k. Capacity explains part, not all, of the
  40k fusion gap.
- `v2_04_ablation`: product-only and absolute-difference-only inputs each
  reproduce the matched-budget gain. The two handcrafted interactions are
  redundant rather than additive.
- `v2_05_types` and addendum: join GQA type/program metadata, compute priors,
  slice checkpoint accuracy and examine lift. Fusion gains concentrate on
  verify/logical/object/relation questions; choose shows a consistent cost.
  Prior-adjusted analysis exposes a deeper-program deficit.
- `v2_06_reliance`: shuffled-image drops are concat 0.1171, product 0.1282 and
  fusion 0.1427. Wrong real images are more damaging than zero vectors and
  fusion's excess reliance concentrates in verify/logical.
- `v2_07_scaling`: at 250k, question-only reaches 0.4977, concat 0.5786,
  product 0.5824 and fusion 0.5823. The handcrafted feature advantage shrinks
  to about 0.004 and is no longer seed-robust. The multimodal margin grows.

### V3 experiments

- `v3_00_tokens`: extracts all projected visual and question tokens with
  atomic partial-store promotion. Normalised stored CLS/EOT states reproduce
  V2 globals within fp16 quantisation. Loader throughput is 24,711 samples/s;
  the padding-mask comparison differs by at most 2.24e-07.
- `v3_01_reasoner`: an eight-point seed-0 optimisation search selects learning
  rate 3e-4, no warmup and dropout 0.1. Three final seeds reach 0.5422 +/-
  0.0037. The mean gap to fusion is +0.0031 +/- 0.0062 and negative in two of
  three seeds. The reasoner does not reduce the compositional deficit and is
  about 19 times larger and 30 times slower at cached-feature inference.
- `v3_02a_refs`: direct-linear reaches 0.4813 with 102,500 parameters;
  meanpatch-concat reaches 0.5145. Image-clustered bootstrap gives repaired
  reasoner deficit 0.0980, fusion deficit 0.0918 and paired difference +0.0047
  with 95% CI [-0.0067, 0.0170]. Test-time CLS removal costs 0.028-0.050
  accuracy. A seed-0 patches-only training probe reaches 0.5359 without
  improving combined >=4 lift.

The defensible current result is negative and bounded: for this frozen encoder,
dataset, 40k scale, architecture and recipe, the 21.1M token reasoner does not
materially beat the 1.1M global fusion head or close the compositional deficit.
The 100k/250k and clean-test questions remain unanswered.

## Environment and execution contracts

- Hardware target: one RTX 4000 Ada Generation with about 20 GB VRAM.
- Environment: project-local Python 3.12 `.venv`, not Conda.
- `/scratch` is node-local. A venv that exists on one node may be absent or
  unusable on another.
- Start a session with `source .venv/bin/activate` and `source env.sh`, then run
  `bash check_env.sh`.
- The path contains spaces; invoke pip as `python -m pip` rather than its
  generated console-script shim.
- `requirements.lock.txt` pins torch 2.12.1/OpenCLIP 3.3.0-era execution, but
  `setup.sh` currently installs the unpinned direct requirements first.
- Global-head training loads aligned arrays into RAM. V3 TokenStores loads
  about 5.8 GB of fp16 data into host memory and yields fp32 samples.
- V3 reasoner workflows are effectively CUDA-only despite a nominal CPU device
  option because autocast, memory and synchronisation calls assume CUDA.

## Binding invariants

- Never open clean-test targets during development and never compute a
  label-derived clean-test statistic.
- Use dev only for search, early stopping, architecture choice and reporting.
- Keep all encoder parameters frozen.
- Keep V1 and V2 label mappings isolated.
- Preserve string IDs and row alignment between a manifest and aligned HDF5.
- Preserve the V2 train-prefix nesting and image-disjoint partitions.
- Require finite 512-dimensional features; global vectors are unit normalised.
- Require V3 image token shape `(50, 512)` and valid packed question spans.
- Interpret `True` in the question mask as padding to ignore.
- Trace every result to a real artifact and identify its protocol/split.
- Treat cached-feature latency as head latency, not end-to-end VQA latency.
- Do not cross the supervisor-feedback gate by treating an unfinished idea as
  approval.

## Audit findings that require future action

These are findings, not silently applied corrections. Address each through a
separate planned, reviewed task before relying on the affected claim.

### Scientific and reproducibility findings

1. Multi-model V2 scripts create one seeded loader per seed and then train
   models sequentially. The loader generator and global torch RNG advance from
   model to model. Stored runs are deterministic in their original order, but
   same-named seeds do not share matched shuffle/initialisation streams and a
   single-model rerun is order-dependent. This weakens the paired-gap wording in
   v2_02, v2_03, v2_04 and v2_07.
2. The v3_02a attention report describes seed-0 ranges as if they covered all
   seeds. Stored seed-by-block means span 0.1805-0.5346, with per-seed means
   0.3803, 0.3340 and 0.2642; per-head means span 0.0530-0.8881 and maximum
   per-example p95 is 0.9931. The report's 0.35-0.40/0.13-0.89/0.92 summary is
   not the all-seed range.
3. v2_07 still uses the older unweighted mean of the 4-step and >=5-step lift
   buckets. Under v3_02a's superseding question-weighted definition, stored
   250k seed-42 deficits are concat 0.08443, fusion 0.08075, product 0.07780
   and question-only 0.07489. The qualitative persistence conclusion remains,
   but the current report understates the deficit and overstates invariance.
4. v2_05 slice-correlation p-values treat 14 overlapping slices as independent.
   The correlations are descriptive; those p-values are not calibrated for the
   overlap. v2_05b row-level intervals also ignore repeated questions per image.
   v3_02a clusters only the repaired step-deficit analysis.
5. v3_01 writes a search grid before execution but later overwrites the same
   JSON with results. The final file alone does not independently prove temporal
   preregistration.
6. Multi-seed result files call top-level `run_metadata()` with its default
   seed 42. Nested run records carry the real seeds, but the top-level field can
   mislead.

### Workflow and implementation findings

1. A fresh v2_00 build-plus-verify is not self-contained. The verifier expects
   `preservation_before.json`, while git-before capture, idempotence append and
   public evidence generation occurred outside the two documented scripts.
2. `setup.sh` installs unpinned requirements rather than the lock file;
   `check_env.sh` checks imports but not pinned versions.
3. `train_model` initialises best accuracy to zero and saves only on strict
   improvement. A model scoring exactly zero throughout produces no checkpoint.
   The returned model is the final epoch, not the saved best state.
4. Dataset loaders assume rather than validate many HDF5 shapes, dtypes, ID
   uniqueness, span bounds, labels and provenance attributes.
5. V1 downloads and HDF5/JSON writes lack the atomic partial-file promotion
   added in V3. Stage 2 treats any non-empty image directory as extracted and
   can skip missing images without storing row IDs.
6. `run_metadata()` omits several claimed provenance elements: dirty-tree
   state, driver, OpenCLIP/numpy/pandas/h5py versions, lock hash and dataset
   hashes. Setting `PYTHONHASHSEED` inside the running interpreter cannot change
   that interpreter's existing hash seed.
7. There is no formal `tests/` suite or CI. Experiment scripts contain useful
   runtime gates, but core schemas, checkpoints, seeding and failure paths lack
   regression tests.
8. V3_01's report says four checkpoints although eight search plus three final
   checkpoints exist. Source/result wording also retains an obsolete claim that
   question-conditioned zero-shot is impossible rather than unimplemented.
9. `run_refs.py --extended` is advertised but exits immediately. Several V3
   signature/gate checks record failure rather than consistently failing the
   process.
10. The local ignored Claude settings contain broad historic SSH, arbitrary
    Python, kill and remote-delete allow patterns. They are not collaboration
    policy and must not be copied into tracked settings.

## Toolkit decision

The linked Everything Claude Code fork was audited at commit
432485ba6b92c14fb357276a98957f348bcff9ee. It contains 81 files: agents,
commands, skills, rules, contexts, Node hooks, tests and MCP templates. It is
not one skill and is not safe to install wholesale here.

Useful patterns adopted here are requirements-first planning, exact paths and
risks, immutable handoffs, review findings ranked by consequence, and an
explicit verification loop. Rejected components are automatic hooks, MCPs,
package-manager setup, `npx` execution, generic web rules, forced model pins,
emoji-heavy output and universal coverage/E2E mandates. The repository-specific
replacement is `.agents/skills/vqa-research-execution/` plus the two read-only
Claude agents and `collab/PROTOCOL.md`.
